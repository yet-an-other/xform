# Country flags from xray's own geoip.dat, resolved server-side

The users table shows a country flag beside each online IP. The IP → country lookup reads xray's own `geoip.dat` (the Loyalsoldier/v2ray protobuf `GeoIPList`) once at startup, via the `xtls/xray-core` generated types — xray-core is already a direct dependency for the stats client, so this costs no new module. The file is found via `XFORM_GEOIP`, falling back to `/usr/local/share/xray/geoip.dat` and the xray config's directory; when it's absent or unreadable the feature is simply off — no error state, no flag placeholders. Only two-letter country categories are used; the file's `private` category and named network groups yield no flag. Countries are resolved at snapshot time and never persisted — a country is re-derivable from the IP, and last-known (stale) IPs keep their flags. The API carries them as an additive `ip_countries` map on each user, leaving `ips` untouched, so an older SPA in the proxy-hosted shape (ADR-0001) keeps working against a newer API. Flags render as regional-indicator emoji built from the ISO code — zero assets; Windows browsers show the two letters instead, which still carry the country. Rejected: MaxMind GeoLite2 `.mmdb` (account, download/update story, redistribution restrictions — for a file the host already has in another format), remote IP-geo APIs (they would ship proxy users' IPs to a third party — disqualifying on a privacy panel), and embedded SVG flags (~250 assets and an upstream license to fix a Windows-only glyph gap).
