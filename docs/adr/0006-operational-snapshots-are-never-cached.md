# Operational snapshots are collected per request and never cached

The panel holds two shapes of data, and they are deliberately handled in opposite ways. Observations — host stats, xray status, user traffic and presence — are gathered on the panel's own five-second cadence into `internal/snapshot.Cache[T]`, which serves the last good one and flags it stale when a refresh fails, so a request is normally answered from memory rather than from a fresh read. Operational snapshots — the Log snapshot and the Config snapshot behind the Viewers — are the opposite: `journal.Reader` and `configsnapshot.Reader` are called directly on every request, hold nothing between calls, and are wrapped in no cache. This is not an oversight in the shape of the code, and it is not a caching layer someone forgot to add. A Log snapshot answers "what does the journal say right now, at the moment I asked", and a cached one would answer a question nobody put; the same holds for the exact text of a file an admin is reading precisely because they suspect it changed. The browser keeps to the same rule — a closed dialog aborts its request and discards its snapshot, so every opening is an initial load — and a server-side cache would quietly defeat that from behind. The Config snapshot's independence is load-bearing in another direction too: it must be able to show malformed JSON at the same moment the Roster is still serving its last valid parse, which a shared cache would collapse into one truth. Caching is genuinely tempting here, because collection is expensive: journalctl runs as a child process under a five-second deadline, a single global process slot, and 8 MiB / 500-entry caps, and that slot is exactly why a second concurrent request is told to retry rather than queued. We pay that cost per request anyway, because these snapshots are admin-initiated and rare, and correctness about "now" is the entire feature. Rejected: wrapping both readers in `snapshot.Cache` like every other source (it would make `captured_at` a lie and turn `Bounded · manual refresh` into a button that sometimes does nothing), and a short-TTL cache to absorb double-clicks (the process slot already bounds concurrency, and a TTL only moves the lie to a smaller window).
