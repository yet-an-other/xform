# Two same-origin deployment shapes: embedded dashboard by default, reverse-proxy-hosted as an alternative

Hosts running xray almost always already front traffic with xray itself (Reality owns :443) and frequently nginx behind it, so serving the dashboard from the Go binary is never strictly necessary. We still keep `embed` as the default shape — one artifact, guaranteed UI/API version match, trivial rollback, no nginx prerequisite for minimal installs — and additionally support nginx (or any existing reverse proxy) serving the built SPA as static files while proxying `/api/*` to the Go API on loopback. Both shapes are **same-origin**: the API emits no CORS headers and the `SameSite=Lax` session cookie works unchanged. Cross-origin or CDN-hosted UI is rejected outright — it would require `SameSite=None; Secure`, a CORS origin allowlist, and CSRF tokens, all cost and no benefit for a single-admin panel.
