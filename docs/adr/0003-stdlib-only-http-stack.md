# Stdlib-only HTTP stack — no router framework, no OpenAPI codegen

The Go API uses only `net/http`: Go 1.22+ `ServeMux` already provides method patterns, wildcards, deterministic precedence, and automatic 405 + `Allow` handling, which covers xform's six-endpoint surface entirely. chi was considered and rejected for now — its remaining value post-Go-1.22 is middleware-grouping sugar we don't need at this size, and because stdlib handlers are chi-compatible, adopting it later (if route-group scoping gets painful past ~15–20 endpoints) is mechanical rather than a rewrite. gin/echo are rejected outright: framework lock-in, non-`net/http` handler signatures, and dependency weight with no benefit at one-dashboard-per-5s load. oapi-codegen is deferred until a second API consumer exists — SPEC.md §5 is the contract document, and the SPA's hand-written client for six flat JSON endpoints is trivial.
