# Tag-gated releases with a SHA-verified host auto-updater

Releases are cut only by pushing `v*` tags — the tag is the approval gate, because the host updater installs what it finds unattended on a production proxy host — and published as **full** GitHub Releases (never the prerelease flag: `/releases/latest`, which the updater polls, ignores prereleases and drafts). Each release carries exactly three assets with names that never change: `xform-linux-amd64`, `xform-linux-arm64`, and `checksums.txt`; the updater compares the local binary's SHA256 against `checksums.txt` rather than parsing version strings, so retagged or rebuilt releases are still detected. These asset names are now a contract with deployed updaters — renaming them breaks installations in the field, which is what makes this decision expensive to reverse. Rejected: every-push rolling releases (no human gate), tarballs/debs/rpms (an unwrap step for nothing — the systemd unit changes rarely and is installed once), GoReleaser (a 60-line workflow covers the matrix), and version-string comparison (fragile in bash; the binary's ldflags-stamped `version` is for humans reading logs, not for the updater's logic).
